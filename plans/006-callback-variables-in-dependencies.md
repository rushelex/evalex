# Зависимости формулы: без имён функций и переменных колбэков

## Резюме

`Expression.extractDependencies()` и `evaluate().dependencies` должны перечислять только переменные контекста, которые формула читает. Сейчас туда попадают имена вызванных функций и локальные переменные колбэков `current` и `index`.

**Цель**: оба набора зависимостей содержат только имена, которые разрешаются из контекста `evaluate({ context })` или из узлов runtime.

---

## 1. Текущее состояние

| Формула | `extractDependencies()` | `evaluate().dependencies` | Ожидается |
|---------|-------------------------|---------------------------|-----------|
| `if(flag, a, b)` | `if, flag, a, b` | `flag, b` | статика `flag, a, b` |
| `items.map(current * index)` | `items, current, index` | `items, current, index` | `items` |
| `e() + pi()` | `e, pi` | — | пусто |

Причины:

- `DependencyExtractorVisitor.visitCallExpressionNode` (`src/core/dependency-extractor.visitor.ts`) обходит `callee`, а для `Identifier` это имя функции.
- `FormulaEvaluatorVisitor.visitIdentifierNode` (`src/core/evaluator.visitor.ts`) зовёт хук `onIdentifier` до разрешения имени и не различает локальную область колбэка и глобальные свойства.
- Статический обходчик не знает, какие аргументы — колбэки и какие имена они вводят: это знает только `CallbackArgument` в описании рутины.

## 2. Последствия

- Runtime строит граф по статическим зависимостям (`FormulaRuntime#fullValidateAndCache`). Узел с id `e`, `today`, `current` или `index` становится ложной зависимостью: его изменение пересчитывает формулу, а ссылка на него попадает в проверку циклов.
- Лимит `MAX_DEPENDENCIES_PER_FORMULA` считает имена функций и переменные колбэков.
- `onCalculate(node, value, dependencies)` отдаёт потребителю `current` и `index`, которых в его данных нет.

## 3. Решения, которые нужно принять

| # | Вопрос | Варианты | Рекомендация |
|---|--------|----------|--------------|
| 1 | Как статике узнать о колбэках | (а) обходчик спрашивает реестр рутин, какие аргументы — `CallbackArgument` и какие имена они вводят; (б) фиксированный список `current`, `index`; (в) не исключать, а только документировать | **(а)**: имена колбэков объявлены в рутине, список (б) разойдётся с первой новой рутиной |
| 2 | Что делать, если в контексте есть глобальная переменная `current` | (а) внутри колбэка она перекрыта и не считается зависимостью; (б) считается | **(а)**: так ведёт себя вычисление |
| 3 | Рантайм-зависимости | хук `onIdentifier` срабатывает, только когда имя разрешилось из глобальных свойств, а не из локальной области | — |

## 4. Этапы

1. **Имена функций.** `visitCallExpressionNode` в обходчике пропускает `callee`, если это `Identifier`.
2. **Рантайм.** `FormulaEvaluationContext` сообщает, из какой области разрешилось имя; хук вызывается только для глобальных.
3. **Статика.** Обходчик получает доступ к реестру и для аргумента-колбэка обходит его с добавленной локальной областью из `CallbackArgument.contextVariables`.
4. **Документация.** Обновить пример в `src/core/README.md` (раздел «Static vs. runtime dependencies»).

## 5. Тесты

- `if(flag, a, b)` → статика `flag, a, b`.
- `items.map(current * index)` → обе формы дают `items`.
- `items.map(current * price)` → `items, price`.
- Контекст с глобальной `current`: `current + items.map(current).sum()` → `current, items`.
- Runtime: узел с id `index` не пересчитывает `items.map(current * index)`.
